# Inventory map UI: sidebar, URL state, symbology, pointer tools, review history

The `/inventory/` map page itself (`map.js` and its shared modules).

*Part of the per-feature reference split out of [CLAUDE.md](../CLAUDE.md) on 2026-11-14 (text moved verbatim). "Above"/"below" references to other sections may now point into a sibling file — the index is in CLAUDE.md.*

## How map.js is being split (started 2026-11-14)

`map.js` is one closure (609 KB before the split). Sections move out one at a
time into their own files, each exposing `window.LS<Name>.init(ctx)`; map.js
calls `init` once, **at the place in its start-up where the code used to
sit**, passing what the section needs under the same names it always used,
so the moved text is unchanged. `home.html` loads the files just before
`map.js`. Snapshots copy the whole static folder and render `home.html`, so
they pick the files up without a change.

| File | Global | What |
|---|---|---|
| `measure.js` | `LSMeasure` | `MeasureControl` (distance / area) and `fmtArea` |
| `opera_hist.js` | `LSOperaHist` | OPERA asc × desc view histogram panel |
| `export_ui.js` | `LSExportUI` | PNG export controls (engine: `ls_export.js`) |
| `insar_ts.js` | `LSInsarTs` | InSAR point time-series tool |
| `photos.js` | `LSPhotos` | Field photos: detail-panel strip, lightbox, map dots |
| `external_inv.js` | `LSExternal` | Mirrored third-party inventories (registry, sidebar rows, bbox fetch, popups); promotion stays in `map.js` |

The method and its static checks are in **`tools/jscheck/README.md`**: list a
section's crossings (`deps.js`), move it (`extract.py`), prove no name was
left behind (`verify.sh`). Sections whose only crossings are functions and
never-reassigned variables move verbatim; the first four were that kind.
Where state was written on both sides (photos, external inventories), the
outside writes were first turned into small functions inside the section
(`_photoShow`, `_photoOpenAt`, `_extEnsureRegistry`, `_extApplyOrDefer`) so
the state became private to it, and then it moved verbatim. **Next, each
needing the same treatment**: trace rasters, the DIST overlay, then the
charts (histogram / timeline), the wiper, and the overlay framework. A new
feature for the map page starts as its own file in this pattern, not as
another section of map.js.

## Inventory map UI structure

The sidebar at `/inventory/` is a three-tab layout with a pinned strip on top:

- **Pinned strip** (always visible above the tabs): the slow/catastrophic type checkboxes and the **Traces** show/hide box (2026-10-06 as *Scarps*; renamed 2026-10-11 when the traces gained kinds). Its last row is the **filter note** (2026-11-05): plain *Unfiltered*, or bold red *FILTERED* with a tooltip naming the filters in force (`_syncFilterNote`, called from `buildFilter` and the cold apply; reads `_filterCollect` + the explorer selection, so a new filter key needs a name in its `NAMES` table; limit-to-view, chart modes and the Traces box do not count). (The basemap quick-select was removed 2026-08 as redundant with the Reference maps tab, which owns basemap choice; "Limit counts to map view" moved into the Inventory tab because it scopes that tab's counts + the analysis charts, not anything universal.)
- **Inventory tab**: "Limit counts to map view" toggle, class checkboxes + dot-color legend + record count breakdown. Every class group header carries scoped all/none links (`.sg-all`/`.sg-none` + `data-sg` rows); the top "Class all/none" pair is global. In-view counting uses the shared `makeViewportTest()` predicate (see HAZARDS.md §globe) — not `queryRenderedFeatures`.
- **Reference maps tab**: categorized basemap cards (Imagery / Topo / Historical / Other) with thumbnails, Windy.com-style. "Reference layers" section for toggleable vector references (faults, survey circles), an **Overlays** section for semi-transparent rasters (see *Raster overlays* below), plus Compare (swipe) and, for editors, Traced imagery. A **＋ Add wiper** button (Compare section; replaces the old pull-down) adds a second, view-synced basemap on the right half of the map behind a draggable vertical divider, and opens a **floating right-pane panel** over the map's right side with its own basemap cards + overlay toggles — the sidebar controls the left pane, the panel controls the right (`_wiperPanelRefresh`/`_syncSwipeUI`; the panel sits at z-index 9, under the detail panel). The wiper starts with both panes on the current basemap — `#swipe-map` is a second `maplibregl.Map` (pointer-events:none, clipped via `clip-path`) carrying the **same data stack in the same draw order** as the main map, so the display reads seamlessly across the divider. `_swipeAddData` builds it from **shared def builders** (`_landslideLayerDefs`, `_suscSourceDef`/`_suscLayerDef`, `_faultsLayerDef`, `_polygonHoverDef`, `_surveyCircleLayerDefs`, `_pendingLayerDefs` — one def = identical paint on both panes; also consumed by `initDataLayers`/`ensurePendingLayers`), in the main map's bottom→top order: pending magenta → susceptibility rasters → faults → points → patchy → polygon fill/outline → hover → survey circles → pin-label. Every toggle/data/hover site mirrors via `_swipeAlso` (susc + faults + survey-circle visibility & data, `polygon-hover` filter via `_setPolygonHover`, `_patchFeatureProp` live edits, `ensurePinLabel`), and the active filter applies to both sides (`_applyLandslideFilter` registry). Only interaction-tool layers (measure, draw draft) are deliberately not mirrored. `_swipeAddData` bails until `initLayers` sets the palette (a hash-restored wiper can create the swipe map first); `initLayers` re-invokes it. Available to everyone; works with any basemap (reprojected Yandex / QMS / AHAP). Toggle classes off for a clean image-only compare.

**Full view state in the URL + per-landslide default views.** The URL hash carries the wiper (`…&swipe=<basemapId>&sx=<divider %>`), the raster overlays (`ov=<id>.l<pct>r<pct>,…` — per-pane visibility + opacity; an explicit `ov=` fully describes the visible set, absence leaves overlay state alone), the active sidebar tab (`tab=refmaps|analysis`, written only when not the inventory default), and the open analysis panels (`an=hist,timing,scatter,opera`) alongside the existing `map=zoom/lat/lon&base=…&id=…`, written on swipe enable/disable/divider-drag and restored on load (also via the `ls_map_view` localStorage view, and re-tried after `api/qms/promoted` merges in case the wiper's basemap is a shared QMS layer — `base=` gets the same wait via `_pendingBase`/`_applyPendingBase`, added 2026-10-06 after a cold load of a link naming a shared layer was found to fall back to the default basemap for everyone). That same hash string (no leading `#`) is the format of **`landslides.default_map_view`** (schema: `migrate_default_view`, idempotent, run per environment) — a curated per-landslide view. Editors set/update/clear it from the map detail panel ("Set default view" saves the *current* center/zoom/basemap/wiper via the `manage_edit_field` autosave endpoint, which validates the string's charset/shape because `slug_redirect` emits it into a Location header); anyone sees a "⌖ Default view" button when one is stored (`applyViewString` in map.js — sets basemap, enables/disables the wiper, flies to the view). Consumed by: slug deep-links (`slug_redirect` prefers it over the centroid+zoom-13 fallback), in-app permalink clicks (`data-view` attr), snapshot slug stubs (`build_snapshot`), and **double-clicking a landslide on the map** (`_dblclickDefaultView` — applies the stored view incl. basemap + wiper, or plain centroid zoom-13 when none is stored; suppresses the map's own double-click zoom on features). Since 2026-09-13 the hash also carries the lidar overlays (`li=<id>.<p>l<pct>r<pct>,…`, p = what to draw: h hillshade | p preset | o ortho, with k a retired read-only alias for preset; same present/absent semantics as `ov`), written on every lidar toggle/preset/opacity change so a default view reproduces the surveys an editor had on; `applyViewString`/hashchange apply it, and `_lidarFetch` applies a `li=` that arrived before the catalog. **How the URL is organised (consolidated 2026-10-06).** One grammar, one table:

- **`ls_hash.js` is the grammar** (parse + encode, shared with `/glaciers/`); its header is the specification. `map.js` no longer has a parser or a writer of its own. The rule for the list params `ov`/`li`/`ext`/`im`/`ref`: **present fully describes the set** (unlisted = off, present-but-empty = none), **absent = leave alone**.
- **`_VIEW_PARAMS` (end of `map.js`) is the one table**: a row per param with `collect(mode, o)` and `apply(s, how)`. Both writers are `_viewStateString(mode)` — `'url'` the address bar, `'saved'` the per-browser last view, `'view'` a stored default view — and both runtime appliers (hashchange, `applyViewString`) are `_applyViewState`. **To make something travel in a link, add a row.** Each row also names where it is consumed on a cold load: `cold: true` goes through the same `apply()`, a string names the place that reads `_initialHash` instead, for the params that are needed while the map is being built or that wait on a fetch (basemap, wiper, overlays, lidar, external layers, imagery, filters). Cold-load timing is real and was left where it is; the table records it rather than hiding it.
- **Filters are in the hash**, with the same value encodings they had in the query string: `ty` types, `c` classes, `f` attribute flags (bitmasks; `f` gained bit 4096 = Flagged, editor-only), `sa`/`da`/`vol`/`yr`/`n10`/`lw` sliders as `lo,hi`, `lv` limit-to-view, `pm` chart modes. A legacy `?t=1&c=5&yr=…` link is still read on load (`_filterColdApply`, same reader), and the first `writeHashState` rewrites it into the hash and drops the old query keys (`?subset=` and anything else stays). `ty` was `t` in the query; it was renamed because `/glaciers/` already uses `t` for time. `?hist=1`/`?timing=1` are read as the old spelling of `an=hist,timing` and no longer written.
- **Filters and the explorer selection are in the address bar only.** They are not saved to `ls_map_view` (a filter must not become the map someone finds days later with most of its records missing) and never written into or applied from a default view (it is permanent and public; a filter in it would hide other records from a visitor who never chose to).
- **A round trip to a record form keeps them, per tab** (2026-11-05, Hig: slow was back on after map → record → ↩ Map). `writeHashState` also keeps the whole `'url'` string in `sessionStorage['ls_map_session']` (`{t, q, v}`); on a load whose link gives no camera — a bare `/inventory/`, or `#id=N` (*View on map*, whose own params go on top) — `_sessionViewRead` restores it, filters and explorer selection included. It lapses 12 h after the map was last touched (the days-later rule above still holds), is ignored unless the query string matches the one it was written under (a legacy `?t=…` link, a `?subset=` page), and a new tab has none, so the explorer's new-tab links and every link with `map=` behave as before. `ls_map_view` is unchanged and is the fallback.
- **`sc=0|1` is the trace toggle** — the **Traces** box in the pinned strip beside Slow / Catastrophic (`cb-scarps` → `LSScarps.setVisible`, which now remembers its state across basemap switches). Written as `sc=0` when hidden; a default view writes it either way. It is its own key rather than a name in `ref=` because scarps are on by default and `ref=` links already in the wild list what is on — adding a name to that set would have hidden scarps on every one of them. Starting a scarp trace from the pencil turns the layer back on.
- **Other params**: `ref=<name>,…` reference vectors (`faults`, `circles`), written only when off the page default of faults-on; a `~YYYY-MM-DD` / `~all` flag on an `ov` entry pins a date-stepper overlay's date (written only for a date the user chose, so a saved view never freezes a row tracking "latest"; a default view always pins it); `li` takes a second shading code before the `r` pane when the panes differ (`homer_2019.hl100pr80`).
- **A stored default view writes `ov`/`li`/`ext`/`im`/`ref` even when empty** and always pins the basemap; views stored before 2026-10-06 lack the empty ones and behave as they always did until re-saved.
- **Additive only.** Stored default views, snapshots and shared links hold these strings for good. Every change above was checked by running the previously deployed parser against the new one over production's stored default views plus hand-written legacy forms (identical on all), and the codec round-trips them. Do the same before the next grammar change.
- **`pr=` carries the elevation profile** (2026-10-08): the line as a flat `lat,lon` list at 5 dp, `pw=d0,d1` its brushed window in metres along the line, `pve=0` when the chart is unlocked from 1:1; absent = leave alone. One `_VIEW_PARAMS` row reads `LSProfile.state()` / calls `LSProfile.setState()`; a line arriving before the lidar catalogue waits for it (`LSProfile.onCatalog`), or it would be read against Mapterhorn alone. It rides in saved views and default views like the overlays.
- **`smp=lat,lon,r_km` is the sample circle** (`ls_sample.js`; `pp=` was its 2026-10-09 name and is still read) and **`ax=<x>,<y>` (read also as `<x>|<y>`, its form until 2026-10-13: a `|` fails `valid_view_state`, so a default view taken with the panel open was refused), `bx=x0,x1,y0,y1`, `ls=count|prop`, `gr=<level>` are the analysis panel's axes, brush, landslide layer and grid step** (`analysis.js`; `an=analysis` opens it; `an=scatter` / `an=pf` are read as `an=analysis` on lw|n10 / pzi|prob when no `ax=` is given — `_AN_ALIASES`). Each is one `_VIEW_PARAMS` row, applied on cold load and hashchange. An `ax=` arriving by URL does NOT re-point the wiper (the URL's own `ov=`/`swipe=` describe the panes); an axis picked in the panel does.
- **`map=` carries the camera: `zoom/lat/lon[/bearing/pitch]`** (2026-10-17, for trailgeek's 3D views; MapLibre's own `hash: true` order). Bearing and pitch are written only when one is non-zero and read as 0 when absent, so every link and stored view so far reads exactly as it did; /inventory/ and /glaciers/ lock north-up and nadir and ignore the two. The writer's lat/lon precision now follows MapLibre's half-pixel rule instead of a fixed 4 dp (4 dp up to z11, 5 at z12–15, 6 at z16–18): a 4 dp link reopened at a lidar zoom landed up to 5 m off. **`node tools/hash_codec_check.js OLD.js NEW.js [strings.txt]`** is the "previously deployed parser against the new one" check above, as a script (old and new must agree on every old field, and the new codec must round-trip its own output); feed it production's stored default views before the next grammar change.
- Not in the URL, by choice so far: the histogram day window, the pinned label field.

**Default views are public, but may name restricted layers** (changed 2026-10-30, Hig: a view was refused for a gated layer on the other side of the planet). `manage_edit_field` stores the view as set and returns `private_layers` (`view_state_private_layers`: browser-local or admins-only QMS basemaps, gated lidar, editor-only uploads, each with who can see it); the client warns, after saving, only about those **inside the frame** (`_viewPrivateInFrame`: a basemap always, lidar by footprint, uploads by bounds). Each visitor is served the view minus what they cannot see: `view_state_for_user` drops unseeable `li=`/`im=` entries in `api_detail`, `slug_redirect` and the explorer's non-editor table (a gated survey's id must not reach them even unused; snapshots go through `api_detail` anonymously), and leaves an unseeable `base=`/`swipe=` for the client to ignore (current basemap kept, no wiper). QMS sharing defaults to admins-only (`QmsLayer.public=False`); editors re-scope an already-shared layer from the card's admins/everyone tag (`_showScopeMenu` → `POST api/qms/<id>/scope/`).
- **Analysis tab**: triggers for the seasonal histogram, time-series chart, the two-axis analysis panel ("Cross two overlays", with preset links for lw × n10, permafrost Obu × Gruber and slope × elevation) and the OPERA view histogram — each opens as a floating, draggable, resizable panel (see *Floating analysis panels* and *The analysis panel* below). The histogram, time-series and analysis points respect the Limit toggle.

(The n10/lw susceptibility range sliders live in the **Inventory** filter panel alongside the source-area / deposit-area / volume / age dual-range filters.)

**Filter parity — points & polygons share one decision path.** `buildFilter()` (map.js) builds a single MapLibre expression `f` and applies it — via the **`_landslideFilterLayers` registry + `_applyLandslideFilter` helper** (one code path used by both `buildFilter` branches *and* the swipe-map mirror, so no hand-maintained id list to forget) — to `points`, `polygon-fill`, `polygon-outline`, `pin-label`, and the `points-patchy` compound-symbol sublayer. A registry entry may carry a `base` filter (points-patchy's `PATCHY_FILTER`) that's **AND-combined** with `f`, so the sublayer tracks the user filter instead of drifting (the bug where the patchy red centers ignored the Flagged filter). Add a future sublayer to the registry with its `base` and it participates automatically. For the filter to behave identically across sources, every property it reads (`flagged`, `year_num`, `area_src/dep`, the boolean flags, …) must exist on **both** the `landslides` source (`api_features`) and the `polygons` source (`api_polygons`). Those properties come from **one SQL fragment, `_FILTER_PROPS_SQL` in views.py**, spliced into both queries — the single source of truth. Add a filterable landslide-level field there once; never hand-mirror it into one query, or that filter silently drops every feature on the other source when active (the bug where checking "Flagged" hid all polygons was `flagged` present on points but missing from the hand-maintained polygon copy). Display-only props (labels/info-box: `unique_name`, `flag_reason`, `owner`, …) stay inline per-endpoint. `n10`/`lw` are the exception — merged client-side onto both sources by `landslide_id`.

There is no on-map legend or floating basemap-picker — those got removed in favor of the Inventory tab's color key.

**Basemap thumbnails** ship as committed static assets at `inventory/static/inventory/img/basemap-thumbs/*.{png,jpg}` (~180 KB total). The HTML template injects a `basemapThumbs` dict into `LS_CONFIG` via `{% static %}` → WhiteNoise serves them with content-hashed filenames + `Cache-Control: max-age=315360000, public, immutable`. The snapshot build sets `staticBase: './static/'` so the same machinery works in the offline bundle.

## Shared basemap handling and map symbology

**Basemap handling is shared** between the main map and this preview map via `inventory/static/inventory/js/basemaps.js` (`window.LSBasemaps`): the built-in basemap descriptors (`DEFAULTS`) **and** the single `buildRasterStyle(bm, opts)` + the tile-URL transforms, so the two maps can't drift (they used to keep duplicate copies). Both load the module, pass `transformRequest: LSBasemaps.transformRequest` at construction, and call `registerProtocols()` once. **All tile-URL transforms funnel through one place** (`buildRasterStyle` for live tiles, `thumbnailUrl` for card previews): `{x}/{y}/{z}` native; `scheme:'tms'`/`{-y}` bottom-origin; `{q}/{quadkey}/{switch:…}/{s}/{subdomain}` rewritten per-tile by `transformRequest` (quadkey computed from z/x/y, loaded as a plain image → no CORS dependency); and **`reproject:'epsg3395'`** warped per-tile by the `reproj` `addProtocol` — a 1-D vertical resample (3857 and 3395 share X/x-tile-index; only latitude→Y differs, ~997 px offset at z12/63°N) that fetches the source 3395 tile(s), canvas-warps, returns JPEG. Reproject needs CORS (canvas readback), so the backend only sets `reproject` for EPSG:3395 services with `cors_status==enabled` (e.g. Yandex Satellite); thumbnails use the un-warped source tile. Add a basemap or a transform **only in basemaps.js**. The edit/review preview map also fetches `api/qms/promoted` so admin-shared QMS layers (incl. reprojected Yandex) are flippable while mapping geometry.

**Map symbology is shared** between the main inventory map, the swipe comparison map, and the edit/review preview map via `inventory/static/inventory/js/ls_colors.js` (`window.LSColors`) — the single source of truth. Styling is **attribute-driven, NOT by `landslide_class`** (so small records keep their real meaning instead of collapsing to a "Small …" color):

- **Dot size** ← `size_inclusion` (included = full dot, excluded = half) — `pointRadius(P, scale)`.
- **Slow color** ← `creep_behavior`: obvious = red, subtle = yellow, geomorph = green. **Patchy obvious** = a yellow dot with a small **red center** — a separate `points-patchy` circle layer (a MapLibre circle is only 2-tone, so the 3-tone symbol needs a sublayer), filtered to slow patchy via `LSColors.PATCHY_FILTER`.
- **Catastrophic color** ← age band from `year_num`: ≥2012 `#2b368f` (deep blue), Modern `#5479bd`, Holocene `#aecbe9`. Precursory creep is the **stroke/halo** (obvious/patchy red, subtle yellow, geomorph green).
- **Incomplete = magenta `#d11fa0`**: a slow record with no `creep_behavior`, or a catastrophic with no resolvable age — the very dimensions display rests on. Surfaces data gaps on the map (the map doubles as a completeness check).
- **Draw order** (`pointSortKey`): ≥2012 cat → slow obvious(+patchy) → slow subtle → Modern → Holocene → slow geomorph.

`api_features` carries `size_inclusion` + `creep_behavior`; `api_polygons` carries `creep_behavior` (so a polygon matches its centroid dot); the edit-preview polygons query carries `landslide_type`/`creep_behavior`/`year_num`. **`year_num` is derived to mirror `derived._resolve_event_era`** (priority: `seismic_datetime` → 4-digit `year_text` → `year_text` Modern/Holocene token → class era token → `date_min`) — defined once in `_FILTER_PROPS_SQL` and repeated in the timed/timeline-event queries + the edit-preview query. This matters because SMALL catastrophic records have `landslide_class = "Small catastrophic landslide"` (no era token), so keying age off the class alone left them magenta even when timed. Add or change a color/expression **only in ls_colors.js**. The legend (home.html `_CLASS_COLOR` + `_HALO_COLOR` + the `_cls_dot.html` partial) mirrors these colors — the two size-only "Small …" rows render a little **row of dots** (their members vary in color), patchy shows a red-center swatch, incomplete is magenta.

## Map tools: profile, copy coords, go-to, probe, pointer policy

**Elevation profile tool (mock-up, 2026-10-08; `inventory/static/inventory/js/profile.js`).** The ∿ mode in the LSTools group: click vertices, double-click or Enter finishes, Esc cancels the line then exits (two-step, like measure); it claims and releases the map through `LSTools.claim/release` like the measure control, so draw and InSAR take over cleanly. On finish the line is sampled every max(0.5 m, min(50 m, length/400)) and read at those points from **every lidar/bathymetry survey in the catalogue whose footprint it crosses** — terrain-RGB PMTiles read directly with pmtiles.js at the survey's deepest useful zoom and decoded in the page (bilinear; alpha-0 pixels are voids) — plus **Mapterhorn** (3DEP 1/3″ in Alaska, terrarium z13, sea = 0 masked) as the reference everywhere. Nothing goes through the server. The floating `#profile-panel` draws one SVG line per DEM (gaps where a survey has no data), **1:1** locks the vertical scale to the horizontal (the profile fits the panel at equal scales, legend moves below the thin band), unlocked fills the panel and labels the exaggeration (`VE ×N`); **SVG** serialises the drawing, **CSV** writes `distance_m, lon, lat, <id>_m…` with a trailing `#` line naming the DEMs and zooms; hovering the chart marks the position on the map. Not yet: the sample spacing and zoom choice are heuristics; slope/aspect, a second profile for comparison, and `/lidar/` (which now has `ls_tools.js`, for the trace tool) are open.

**Right-click → copy coords:** right-click (Ctrl-click on Mac) anywhere on the main map *or* the edit preview map copies `lat, lon` to the clipboard (for pasting into Planet etc.) with a brief toast. Suppressed while any tool holds the map — measure, draw, InSAR or the outline reviser (there right-click deletes a vertex); the guard is `LSTools.blocked()` on the main map and `__lsTdActive` on the edit preview map. **Paste → go to** (`ls_goto.js`, `LSGoto`, 2026-10-12, on `/inventory/` and `/lidar/`): the reverse of the copy — a ⌖ button under the zoom buttons opens a small `lat, lon` box (Enter goes, Esc closes), and pasting coordinates anywhere outside a text field goes straight there; the spot is ringed until the next map click. `LSGoto.parse` takes decimal (lat first; a first value beyond ±90 is read as lon), N/S/E/W before or after, degrees-minutes-seconds, and map links with `@lat,lon` / `q=`; an unsigned Alaskan longitude is taken as written (east), not guessed. **Alt-click (Option-click) → elevation probe** (main map only): a popup with lat, lon and the height from every lidar survey turned on in either pane whose footprint covers the point, plus Mapterhorn, read in the page by `LSProfile.pointElevations` (each survey at its deepest zoom, bilinear) each with its vertical datum (the catalogue's `vertical_datum`, worded as in the manifest), with a Copy button (tab-separated lines). It is the `probe` click kind in `ls_tools.js`: runs alone, only when no tool holds the map, so it never also opens the record underneath. **Pointer policy — who owns a click, a drag, the cursor and Escape — is declared once in `inventory/static/inventory/js/ls_tools.js`** (header comment is the spec): one `map.on('click')` dispatcher, every clickable thing registers with a kind (`action` / `navigate` / `record` / `reference`) and a priority; a `record` and the highest `reference` may both fire (the declared co-activation), one reference popup slot, tool cursor outranks hover, `LSTools.drag` ends a gesture exactly once, Escape is two-step (cancel, then exit). Add a clickable layer by registering it, never with another `map.on('click')`.

## Imagery review history (deployed 2026-10-26)

What each signed-in user has looked at on `/inventory/`, on which basemap,
for how long — so a reviewer can see what they have covered, and (with the
date) which release of a swapped-out provider like ESRI World Imagery they
saw. Server `inventory/review.py` (its docstring is the design note), client
`ls_review.js`, models `ReviewView` + `ReviewSharing` in **SQLite** (user
activity, like the audit log; migration `0008`, auto-applied).

- **Recording.** A view = the map at rest with its tiles drawn (`idle`) until
  the next move, a basemap/wiper change (`LSReview.layoutChanged()` from
  `setBasemap`, `_swipeEnable/Disable/SetBasemap`, divider drag end), the tab
  hiding, or 2 min without input (dwell cut back to last input + 2 min).
  Each wiper pane is its own record. **Below z10 nothing is recorded** (the
  lidar list's threshold: navigation, not review); `blank` is skipped.
  **High-res layers win**: a lidar survey on in that pane whose footprint
  touches the frame, or (main pane) an uploaded image whose bounds do, is
  taken to be what is looked at, and the view is credited to `lidar:<id>` /
  `trace:<id>` instead of the basemap (several share it, `k`). Low-res
  overlays are ignored. `writeHashState` calls `layoutChanged()`, which ends
  the view only when the frame or that attribution changed. Batches post every 30 s and on `pagehide`. **Anonymous visitors
  are never recorded**: `home.html` sets `LS_CONFIG.review` and loads the
  script only for `user.is_authenticated`, and the endpoints refuse
  anonymous calls (snapshots render anonymously, so they carry none of it).
